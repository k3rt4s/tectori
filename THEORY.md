# THEORY

What a session needs to believe before it changes anything in this repo.

## Invariants

- `docs/` is generated output, not source. `scripts/build_site.py` renders every page, `CNAME`, `robots.txt`, `sitemap.xml`, `llms.txt`, the stylesheet and the script from `site/` and copies the images. A hand edit under `docs/` is overwritten by the next build. Rebuild with `--out docs` and run `scripts/check_site.py` before a deploy.
- Line endings belong to the repository, not to whoever clones it. `.gitattributes` pins them: blobs LF, working copies CRLF except `.gitignore`, `.env.example`, `CLAUDE.md`, `docs/CNAME` and the one `.svg`. A scripted edit that writes LF elsewhere corrupts the diff for the whole file, so count bare LFs after any splice.
- Business values are declared once in `site/content/site.json`, the person in `founder.json` beside it, and reach a page only through a token. A literal in a fragment or in `verify_site.py` passes every check (the built tree is right for this owner either way); only `rehearse_rebrand.py` catches it by changing every value, so run `check_site.py --full` before pushing any check that names one. Tokens resolve in `pages.json` after parsing, and the JSON-LD address derives from the one declared string by `address_parts`.
- The brand name, the founder's job title and biography are the exception: body copy a new owner rewrites, so the rehearsal counts them and names the pages rather than failing, since tokenizing prose would make it unreadable. The founder's name, given name and anchor are not copy: they carry a real person into structured data, so a rebrand that leaves one behind fails.
- A check that confirms a value is present cannot see it in a second place it should not be, which is where every defect found here has been. When adding a check, ask what tree passes it while being wrong, and whether a new owner could produce it. Most such trees were markup a browser reads and a check did not (an attribute reordered, unquoted, inside another's value, a commented-out tag, a second element), so a check tokenises attributes by whole name and ignores comments.
- The site claims no clients, client counts, testimonials, ratings, prices or client results, and names no former employer; career results are fine. Copy never implies employees beyond the founder, nor frames the practice as one person. The credential is Internal Security Assessor (ISA), never Qualified Security Assessor. `verify_site.py` checks the markup and the credential, never the prose.
- `login.html` holds the tree's only CSP and is rendered from `site/pages/login.page.frag` without the shared chrome, which is what `VERBATIM_PAGES` in the build is for. It has no content-model entry but still goes through token substitution.

## Load-bearing constraints

- GitHub Pages serves both `/page` and `/page.html` with 200. Canonicals and every internal link are extensionless and old `.html` links still resolve, so Search Console's "Alternate page with proper canonical tag" is that behavior, not a defect; a host that serves files literally (S3, default nginx) returns 404 on every link while every check passes. Moving off Pages means giving the new host that rewrite first.
- The deploy job in `.github/workflows/verify.yml` is the only route to the site, and the repository publishes from the workflow rather than from the branch. A push to `main` is the go-live only if the checks pass, and the `if` requires `github.ref == 'refs/heads/main'`, so a manual run elsewhere deploys nothing. Group `pages` is on that job alone, the verify job has its own cancelling group, and `check_deploy_gate.py` fails a workflow-level group or a group on any other job. Deleting that job or breaking the upload ships nothing (before 2026-09-12 a red run shipped anyway). The Pages setting sets the domain now, not `docs/CNAME`, which is kept correct only in case anyone publishes from the branch again.
- The domain is one value. Nothing under `site/` spells it out but `site_url`: canonicals and og:url are stored site-relative, the fragments carry `{{SITE_URL}}`, `{{SITE_HOST}}` and `{{SITE_APEX}}`, and changing it reaches every file.
- The contact form submits with JavaScript (`site/static/contact-form.js`, `/contact` only), fetching the Formspree endpoint with `Accept: application/json` so the visitor stays on the page: the free plan ignores `_next` and lands a plain POST on its own thank-you page (2026-09-29). With JavaScript off it posts the old way and lands there, the accepted fallback, so `_next` and its absolute URL stay.
- `scripts/compare_render.py` proves render equality, not byte equality, and only at the top level of each directory (every page is top level and the build creates no directory). It is sound only because every chrome container is a flex or grid box in `styles.css`, where whitespace-only text generates no boxes, and no page contains a `pre`. Break either and reformatting needs a different proof.
- The `insights*.body.frag` pages and their `pages.json` entries are generated. `newsletter_linkedin export-site` in the personal-automation repo writes them from its post database; an edit here is overwritten on the next export. It publishes on the article's evaluation score (>= 8), never the LinkedIn send status, which tracks a send rule rather than a page. It holds back four classes: Jon named in the third person, the drafting prompt leaking in, the source's own first-person voice (which reads as Tectori's claim), and several outlets on one disclosure, hand-judged in `DUPLICATE_GROUPS`. They are tracked source on purpose: `check_source_only_build.py` rebuilds from git alone, so the build may not read that database. Each archive page is one ISO week; a closed week never changes, so a link never moves. Posts credit the publication by name with no link: `site.json` is a closed egress allowlist and `BARE_HOST_RE` in `verify_site.py` fails a hostname in prose.
- The exporter writes the `insights-2026-w*` fragments with LF working copies. Git normalizes them on add, so the deploy is right, but in that checkout `check_site.py --full` and `check_live_deploy.py` fail on those pages. `git ls-files --eol` lists them; `git checkout --` them and `docs/` before calling it a fault.
- The hero uses `min-height`: wrapping copy grows it rather than clipping.
- `llms.txt` is a projection of the pages, not a file: heading, summary blockquote and `- [title](url): description` lines come from the same title, `site_url` and description the pages render with, and `verify_site.py` compares them back, so a bracketed title stops the build rather than ship a broken link.
- Image sizes are never literals: the build reads the logo's and the social card's pixel size from the file and writes `width`, `height` and `og:image:width/height` from it, so replacing an image never needs a markup edit, and `verify_site.py` measures the file again.
- Feed and week pages are derived twice over. An `insights.xml` pubDate is the record's date clamped into the ISO week its page names, because the source article's date is not when Tectori published it; the week pages' JSON-LD (WebPage plus Home, Insights, week breadcrumb) is synthesised by the build from the entry's title, which must read `Insights, <label> | <brand>`, and the suite checks both.
- `rehearse_rebrand.py` marks its output with `.tectori-rehearsal` and refuses to clear a non-empty directory without one, or one inside or above the repo. A rehearsal directory left by the old script (default under the user temp dir) fails `check_site.py --full` until deleted by hand once.
- Changing a page's words means bumping its `lastmod` in `site/content/public_pages.json`, or the sitemap date check fails one step from its cause.
- The accessibility statement is load-bearing: `check_colour_contrast` enforces the WCAG level it publishes, so editing it changes the check. Control borders (SC 1.4.11) and nav target heights (SC 2.5.8) use selector tables in `verify_site.py`; a new bordered control or nav link fails as unmeasured until added to them.

## Decisions that look wrong

- "Audit-ready IT that scales with your ambition." is the brand tagline, not homepage copy. One declared value renders it as the footer line, the social image alt text, the homepage H1 and the homepage og:description, so changing it is a brand call rather than a copy edit.
- The homepage eyebrow reads "Built to be reviewed" because the H1 below it already opens with "Audit-ready".
- The displayed phone number is plain characters inside a `nowrap` span: `&nbsp;` and `&#8209;` put U+00A0 and U+2011 into copied text, which some dialers reject, and the span already prevents the line break.
- Tectori is nationally targeted and Nashville is location proof (Jon, 2026-09-11): no location pages, LocalBusiness schema or Nashville keyword targets. `contact`, `about` and `service-fractional-leadership` name Nashville in title and description as proof, not drift. Reopen only if Search Console shows local query volume.
- `docs/404.html` deliberately has no canonical, and its links and assets are root-absolute so it renders for a deep path, which is why reviewing it needs a local server, not a `file://` open.
- The tree is licensed in two halves along the rehearsal's split: `LICENSE` publishes the generator, checks, chrome and runbooks for review only; `NOTICE` reserves everything `rehearse_rebrand.py` replaces or counts (declared values, founder, copy, images, `docs/`). Jon chose it 2026-09-14: a permissive license cannot be taken back, this one can be loosened. No notice file may live in `docs/` or `site/static/assets/` (the build copies one into the other and `--check` fails on a file it did not write); the residue scan reads `docs/` only, so a root file may name the domain.

## Known soft spots

- The analytics beacon and the Scarf pixel have never been observed in a browser. Verified only: the tags ship on public pages, not on `login.html`, and both endpoints answer.
